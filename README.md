# 피부과 가격 추적기

유앤아이의원 수원점(<https://www.swuni114.co.kr/>) 메인 페이지의 이벤트 가격을 하루 여러 번 수집해
가격 변동·신규·종료 항목을 기록하고, 시술별 가격 추이를 정적 페이지로 만들어 주는 개인용 도구입니다.

- 서버가 필요 없습니다. GitHub 저장소 하나와 GitHub Actions, GitHub Pages만으로 동작합니다.
- 알림은 보내지 않습니다. 변동 내역은 `CHANGES.md`, 그래프는 `index.html`에서 확인합니다.
- 운영 비용은 0원입니다(공개 저장소 + 무료 Actions/Pages).

## 동작 흐름

1. GitHub Actions가 **4시간 간격(하루 6회)** 으로 `python -m tracker`를 실행합니다. cron 지연에 대비해 여러 번 예약하며, 같은 날 재실행은 그날 기록을 교체하므로 중복되지 않습니다. **`main`에 push할 때**도 실행됩니다.
   (생성 파일만 바뀐 봇 커밋은 다시 실행하지 않습니다.)
2. 이벤트 페이지 HTML을 요청해 `카테고리 · 시술명 · 정가 · 할인가`와 전체 이벤트 기간(`#eventDateText`)을 추출합니다.
3. 저장소의 `prices.json`(직전 결과)과 비교해 **가격 인하 / 인상 / 신규 / 종료**를 판정합니다.
   같은 날 재실행이면 하루 안의 재수집이 신규·종료로 잘못 남지 않도록 직전 수집일 스냅샷을 기준으로 다시 계산합니다.
4. 변동이 있으면 `CHANGES.md` 맨 위에 날짜별 요약을 추가합니다.
5. 현재 결과를 `prices.json`에 저장하고, `history.csv`에 그날의 가격을 누적합니다.
6. `history.csv`로 시술별 추이 페이지(`index.html`)를 다시 만들어 함께 커밋합니다.
7. GitHub Pages가 `index.html`을 게시합니다.

페이지 요청이 실패하거나, 추적 대상 건수가 0이거나 직전보다 크게 줄거나, 기존 이력 파일이 손상되면 **가격 데이터를 덮어쓰지 않고 실행을 실패로 표시**합니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `config.json` | 추적 범위(제외 키워드), 안전장치, 저장소 주소 설정 |
| `prices.json` | 직전 실행 결과(현재 판매 중인 항목의 최신 가격과 발견/확인 날짜) |
| `history.csv` | 날짜별 가격 이력. 그래프의 원본 데이터 |
| `CHANGES.md` | 변동이 있었던 날의 요약. 최신 항목이 위에 쌓임 |
| `index.html` | 최근 변동·월별 요약·예상 결제액 탭, 카드/표 보기, 필터·정렬, 상세 차트를 담은 페이지 골격(생성 파일, GitHub Pages로 게시) |
| `assets/data.js` | 그래프 페이지가 읽는 가격 데이터(생성 파일). 내용 해시를 붙여 캐시합니다 |
| `assets/style.css`, `assets/app.js` | 그래프 페이지의 스타일·스크립트(생성 파일). 내용 해시를 붙여 캐시하고, 바뀔 때만 새로 받습니다 |
| `assets/vendor/chart.umd.min.js` | 상세 차트에 쓰는 [Chart.js](https://www.chartjs.org) 4.6.1(MIT, 자체 호스팅) |
| `manifest.webmanifest` | 홈 화면에 추가(PWA)할 때 쓰는 앱 이름·색·아이콘·바로가기 설정(정적 파일) |
| `icons/` | 앱 아이콘. `icon.svg`·`icon-maskable.svg` 원본과 192·512·maskable 512·180 PNG |
| `sw.js` | 오프라인 열람용 서비스 워커(생성 파일). 페이지를 만들 때 캐시 이름과 미리 받을 파일 목록(배너 이미지 포함)이 채워집니다 |
| `tracker/templates/` | `index.html` 골격, `style.css`, `app.js`, `sw.js`, `vendor/` 원본 |
| `tracker/` | 수집·비교·기록·그래프 생성 코드 |
| `tests/` | 파서·비교·변동 계산·요약·이력·그래프·전체 흐름 테스트와 `test_app.js`(대시보드 JS 로직) |
| `.github/workflows/track.yml` | 4시간 간격·push 시 실행 + 결과 커밋 워크플로 |

### 코드 구조

파이썬 코드는 "바깥 세계와 닿는 부분"과 "판단만 하는 부분"을 함수 경계로 나눕니다.
아래 방향으로만 의존합니다.

| 모듈 | 역할 |
| --- | --- |
| `tracker/scrape.py` | 페이지 요청과 HTML 파싱 (네트워크·파서) |
| `tracker/prices.py`, `tracker/history.py` | 스냅샷·이력 파일 읽기/쓰기와 같은 날 스냅샷 교체·병합 |
| `tracker/snapshot.py` | 수집 결과 검증과 `first_seen`/`last_seen` 채우기 (I/O 없음) |
| `tracker/compare.py` | 직전 스냅샷과 비교해 인하·인상·신규·재등장·종료 판정 |
| `tracker/changes.py` | 이번 실행 변동과 이력 기반 최근·월별 요약 계산 (I/O 없음) |
| `tracker/report.py` | `CHANGES.md` 요약 생성 |
| `tracker/graph.py` | 페이지 페이로드·HTML·정적 자산·서비스 워커 생성 |
| `tracker/main.py` | CLI 인자 해석과 수집→검증→기록→페이지 생성 실행 순서 조립 |

`compare.py`·`changes.py`·`snapshot.py`는 파일이나 네트워크를 건드리지 않으므로
테스트에서 입력만 만들어 바로 검증할 수 있습니다.

## 로컬에서 실행하기

Python 3.11 이상이 필요합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt

# 수집 결과만 확인 (파일 쓰지 않음)
python -m tracker --dry-run

# 수집한 시술명·가격을 표로 출력 (파일 쓰지 않음)
python -m tracker --list-items

# 저장해 둔 HTML로 네트워크 없이 실행 (개발·테스트용)
python -m tracker --offline-html page.html

# 실제 실행: prices.json / history.csv / CHANGES.md / index.html / assets / sw.js 갱신
python -m tracker
```

`index.html`은 파일을 브라우저로 열거나, 폴더에서 `python -m http.server 8000`을 실행해
<http://localhost:8000/index.html>로 확인할 수 있습니다.
서비스 워커(PWA)는 `file://`이 아니라 `http://localhost` 같은 보안 컨텍스트에서만 동작합니다.

페이지는 매일 바뀌는 `assets/data.js`(가격 데이터)와 잘 바뀌지 않는 `index.html` 골격,
`assets/style.css`·`assets/app.js`·`assets/vendor/`로 나뉩니다. 모든 자산 주소에는 내용 해시(`assets/app.js?v=…`)가
붙어서, 바뀌지 않은 파일은 브라우저가 캐시에서 그대로 씁니다. 자산을 고쳤다면 `python -m tracker`를 한 번
실행해 `assets/`와 `sw.js`를 다시 만들고 함께 커밋하세요.

테스트:

```powershell
python -m pytest -q              # 수집·비교·생성 로직
node --test tests/test_app.js    # 대시보드 JS 로직
mypy tracker                     # 정적 타입 검사
```

## 그래프 페이지 사용법

- **요약 탭**: 페이지 상단은 **최근 변동 / 월별 가격 요약 / 예상 결제액** 세 탭으로 나뉩니다.
  탭을 누르거나 키보드 좌우 화살표(Home/End 포함)로 이동할 수 있고, 접기 버튼으로 요약 영역 전체를 접을 수 있습니다.
- **예상 결제액 계산**: 시술 상세에서 **계산에 담기**를 누르면 상단 **예상 결제액** 탭의 계산기에 추가됩니다. 같은 상품을 다시 담으면 수량이 늘어납니다.
  상세 창의 **계산 내역 보기**로 이동해 수량(상품별 1~99개)을 바꾸거나, 개별 삭제·전체 비우기를 할 수 있습니다.
  수량 1은 표시된 상품·패키지 1개입니다. 예를 들어 5회 패키지 2개를 담으면 패키지 가격의 2배로 계산합니다.
  기본은 사이트와 같은 **VAT 별도**이며, VAT는 전체 시술 합계의 10%를 원 단위로 반올림합니다.
  상품 선택·수량·VAT 설정은 브라우저에 저장되고, 다음 방문에는 최신 수집 가격을 적용합니다. 종료되거나 찾을 수 없는 상품은 내역에 남기되 합계에서 제외합니다.
  이벤트 중복 적용·첫방문 등 조건에 따라 실제 결제액은 달라질 수 있습니다.
- **재등장 감지**: 같은 카테고리·시술명이 수집 기록에서 빠졌다 다시 나타나면 신규 대신 재등장으로 집계합니다.
  최근 변동·카드·표·상세 창에서 재등장 날짜와 종료 전 마지막 가격 대비 차이를 확인할 수 있으며, `CHANGES.md`에도 기록합니다.
  카테고리나 시술명이 바뀌면 별도 항목입니다. 수집 자체가 없었던 날은 종료로 판단하지 않습니다.
- **월별 가격 요약**: 기본은 마지막 수집 월이며, 월 선택으로 과거 기록도 확인합니다.
  인하·인상·신규·재등장·종료는 수집일 사이에 감지된 횟수입니다. 같은 시술의 반복 변동도 각각 셉니다.
  각 종류 버튼을 누르면 해당 월의 변동 전체가 최근 날짜순으로 펼쳐집니다. 건수가 0인 버튼은 비활성화됩니다.
  같은 버튼을 다시 누르면 인하 금액 TOP 5로 돌아가고, 월을 바꾸면 종류 선택이 초기화됩니다.
  첫 수집일은 기준 데이터로 제외하고, 월 첫 수집은 이전 달의 마지막 수집일과 비교합니다.
  **인하 금액 TOP 5**는 시술별 가장 큰 1회 인하 금액 기준이며, 항목을 누르면 상세 차트가 열립니다.
  재등장 전후 가격 차이는 인하·인상 건수와 순위에 중복 반영하지 않습니다. 수집된 기간만 집계하며 같은 날 재실행해도 중복되지 않습니다.
- **최근 변동**(페이지 상단): 직전 수집일과의 비교 기간·총 변동 건수를 표시하고, 펼치면 인하·인상·신규·재등장·종료 항목을 보여줍니다. 종류별 집계 배지는 월별 요약에만 표시합니다.
  항목을 누르면 해당 시술의 그래프가 열립니다. 기록이 하루뿐이면 기준 데이터 안내가 표시됩니다.
- **상세 창**: 카드·표·변동 내역에서 시술을 누르면 열립니다. 맨 위 **가격 히어로**에 현재가(종료된 항목은 마지막 확인가)를 크게 보여주고,
  정가·할인율·회당 단가를 함께 표시합니다. 아래 **요약 카드**에는 역대 최저·역대 평균·30일 최저·첫 기록 대비를 2×2로 정리합니다.
  **계산에 담기** 옆의 **병원 이벤트 목록 보기**로 원본 페이지를 새 탭에서 열고, 날짜별 가격은 최근 5건만 보여준 뒤 **전체 이력 펼치기**로 과거 기록을 확인합니다.
  맨 아래에는 마지막 수집일이 표시됩니다.
- **변동만**: 직전 수집일 대비 가격이 바뀌었거나 새로 생기고 사라진 시술만 남깁니다.
- **예산 필터**: 카테고리 칩 아래의 **예산** 칩에서 `~3만원`·`~5만원`·`~10만원`·`10만원+` 중 하나를 누르면 그 금액 범위의 시술만 남습니다.
  앞 세 칩은 누적 상한(예: `~5만원` = 5만원 이하 전체)이고, 마지막 칩만 10만원 초과입니다. 카테고리·검색어·관심 필터와 함께 적용되며,
  VAT 포함 표시 중에는 화면에 보이는 금액 기준으로 판정합니다.
- **VAT 포함 표시**: 툴바의 **VAT 포함**을 누르면 목록·표·상세 차트·변동 내역의 금액이 부가세 10%를 더한 결제 예상가(원 단위 반올림)로 바뀝니다.
  선택은 브라우저에 저장되어 다음 방문에도 유지되며, 예상 결제액 계산기의 VAT 스위치와도 함께 움직입니다. 푸터에서 현재 표시 기준을 확인할 수 있습니다.
  목록·표는 항목마다 VAT를 반올림하고 계산기는 시술 합계에 한 번에 적용하므로, VAT 포함 금액을 더한 값과 계산기 총액은 1~2원 차이가 날 수 있습니다.
- **패키지 회당 단가**: `리투오 5cc 3회`처럼 이름 끝에 회차가 있는 항목은 카드·표·상세 창에 **회당 단가**를 함께 보여줍니다.
  상세 창에서는 같은 시술의 `1회·2회·3회…`를 회차순 비교표로 보여주고, 회당 단가가 가장 낮은 회차에 **회당 최저**를 표시합니다.
  같은 이름의 **1회** 항목이 있으면 `1회 대비 23% 저렴`처럼 비교해 주고, 회당 단가가 더 비싸면 `비쌈`으로 표시합니다.
  이름이 `5회 패키지`, `3회+co2 1회 (…)`처럼 회차로 끝나지 않으면 잘못 계산하지 않도록 건너뜁니다.
- **회당 단가 정렬**: 정렬에서 **회당 단가 낮은순**을 고르면 회차를 알 수 없는 항목을 뒤로 보내고 회당 가격이 싼 순서로 보여줍니다.
- **중복 숨기기**: 같은 시술이 `리투오`, `✨ECM부스터 리투오`, `입고 연장 이벤트`처럼 여러 카테고리에 중복 등록된 경우
  **필터 → 중복 숨기기**로 한 번만 표시합니다. 이름 안에 카테고리명이 들어 있는 항목을 우선하고, 판매 중인 항목을 종료된 항목보다 먼저 고릅니다.
  카테고리를 직접 고른 경우에는 그 카테고리 안에서만 중복을 정리합니다.
- **이벤트 D-day**: 원본 페이지의 전체 이벤트 기간을 읽어 목록 위에 `D-11` 배지를 보여줍니다.
  종료 당일에는 `D-DAY`, 기간이 지나면 `종료`와 함께 가격이 갱신됐을 수 있다는 안내로 바뀝니다.
- **다크 모드**: 오른쪽 위 해/달 버튼으로 전환합니다. 기본은 **라이트 모드**이며 시스템 설정을 따르지 않습니다.
  선택은 브라우저에 저장되고, 상세 차트를 열어 둔 상태에서 전환하면 차트 색상도 즉시 바뀝니다.
- **관심 시술**: 상세 창 오른쪽 위 **☆**를 누르면 브라우저에 저장됩니다. 툴바의 **관심 N** 버튼으로 저장한 시술만 모아 볼 수 있고,
  새로고침해도 유지됩니다(저장 값은 서버로 전송되지 않습니다).
- **초성 검색**: 검색창에 `ㅍㅋㅌㄴ`처럼 초성만 입력해도 피코토닝을 찾습니다. 영문·숫자·띄어쓰기가 달라도 함께 검색됩니다.
- **공유**: 상세 창의 공유 버튼으로 해당 시술의 링크를 보낼 수 있습니다. 링크를 열면 그 시술의 그래프가 바로 열립니다.
  모바일에서는 뒤로 가기로 상세 창을 닫을 수 있습니다.
- **정렬**: 카테고리순, 최근 변동순, 할인율 높은순, 가격 높은순/낮은순, 회당 단가 낮은순, 이름순 중에서 고릅니다.
  카테고리순이 아닌 정렬에서는 배너 없는 컴팩트 카드로 표시되어 한 화면에 더 많이 볼 수 있습니다.
- **역대 최저·30일 최저** 배지: 현재가가 수집 이래 또는 최근 30일 중 가장 낮을 때 표시합니다.
  가격이 한 번도 변하지 않은 항목에는 붙지 않습니다.
- 가격 추이 그래프는 **Chart.js**로 그립니다. 완만한 곡선과 그라데이션, 마지막 가격 말풍선을 쓰고,
  점선으로 **역대 최저**와 **평균가**를 함께 보여줍니다.
  데스크톱에서는 마우스를, 모바일에서는 손가락을 올리면 그날의 가격과 직전 대비 변동이 툴팁으로 나타납니다.
  가격이 한 번도 변하지 않은 시술은 **가격 변동 없음** 안내와 함께 평평한 선으로 표시됩니다.
- 기본 화면은 원본 이벤트 페이지처럼 배너가 있는 카테고리 카드입니다. 카드 안의 **펼치기**로 해당 카테고리의 시술을 펼치고, **표로 보기**로 가격 비교 표를 열 수 있습니다.
- **전체 펼치기**로 현재 불러온 카드를 한 번에 펼치거나 접을 수 있습니다.
- 카드에 시술이 2개 이하이면 모두 펼쳐진 상태로 표시되므로 하단 버튼이 없습니다. 각 시술 오른쪽 **↗**를 누르면 가격 추이 그래프가 열립니다.
- 첫방문·이달의 단독 이벤트 카드 배너는 [유앤아이의원 수원점](https://www.swuni114.co.kr/)의 공개 이미지를 사용합니다.
- **카테고리 칩**: 목록 위 가로 스크롤 칩으로 카테고리를 고릅니다.
  새로고침하거나 링크로 열어도 선택한 칩이 보이도록 자동으로 스크롤됩니다.
- **모바일 상세 필터**: 좁은 화면에서는 **필터** 버튼으로 상세 필터·보기 설정을 드로어로 엽니다.
  드로어 바깥을 누르거나 Esc로 닫을 수 있습니다.
- 목록은 **40개씩 / 100개씩 / 전체** 중에서 고를 수 있고, **다음 N개 보기**로 더 불러옵니다.
  카테고리순에서는 카드가 페이지 경계에서 쪼개지지 않도록 카테고리 단위로 잘라서 불러옵니다.
  모바일에서는 카드가 한 열로 정렬되고 오른쪽 아래 **맨 위로** 버튼이 표시됩니다.
- 검색·필터·정렬·보기 방식은 URL 쿼리에 반영되어 새로고침하거나 링크로 공유해도 유지됩니다.
- 마지막 수집이 2일 이상 지나면 페이지 상단에 수집 지연 안내와 GitHub Actions 링크가 나타납니다.
- 검색창은 `/` 키로 바로 포커스할 수 있고, 결과가 없을 때 **필터 초기화** 버튼으로 되돌릴 수 있습니다.

## 홈 화면에 추가(PWA)

휴대폰 브라우저로 <https://miv2.github.io/price-tracker/>를 연 뒤 다음 중 하나를 실행합니다.

- **Android Chrome**: 페이지 아래 **앱으로 설치** 버튼을 누르거나, 오른쪽 위 ⋮ → **앱 설치**
- **iPhone Safari**: 공유 → **홈 화면에 추가**

설치하면 주소창 없이 앱처럼 열립니다. 한 번 열어 둔 페이지는 **인터넷이 끊겨도 마지막으로 받은 가격**으로 열리고,
다시 연결되면 자동으로 최신 데이터를 받습니다.

`sw.js`는 `tracker/templates/sw.js`에서 생성되며, 자산·데이터 해시로 캐시 이름을 만들기 때문에
파일이 바뀌면 이전 캐시를 자동으로 지웁니다. 첫 설치 때 페이지·스크립트·스타일·아이콘과 카드 배너 이미지까지
미리 받아 두므로 오프라인에서도 마지막 화면을 그대로 볼 수 있습니다. 아이콘 원본은 `icons/icon.svg`·`icons/icon-maskable.svg`이고,
PNG(192·512·maskable 512·apple-touch 180)는 원본을 렌더링해 커밋해 둡니다.

## config.json

```json
{
  "source_url": "https://www.swuni114.co.kr/",
  "exclude_keywords": [],
  "bulk_change_threshold": 10,
  "min_items_ratio": 0.5,
  "timeout_seconds": 30,
  "retries": 3,
  "retry_delay_seconds": 5,
  "repo_url": ""
}
```

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `source_url` | 수원점 메인 | 수집할 페이지 주소 |
| `exclude_keywords` | `[]` | 추적에서 뺄 키워드. **카테고리 또는 시술명에 포함**되면 제외합니다. 비워 두면 전체 시술을 추적합니다. |
| `bulk_change_threshold` | `10` | 신규+종료가 이 수 이상이면 건별 대신 하나의 묶음 요약으로 기록합니다(월 전환 대응). |
| `min_items_ratio` | `0.5` | 직전 대비 추출 건수가 이 비율보다 적으면 실행 실패로 처리합니다. |
| `timeout_seconds` | `30` | 페이지 요청 타임아웃 |
| `retries` | `3` | 요청 재시도 횟수 |
| `retry_delay_seconds` | `5` | 재시도 사이 대기 시간 |
| `repo_url` | `""` | 예: `https://github.com/내계정/저장소`. 넣으면 그래프 페이지의 CHANGES/CSV 링크가 GitHub 파일로 연결됩니다. |

제외 키워드를 나중에 추가해도, 기존 항목이 실수로 "종료"로 기록되지는 않습니다.

## 데이터 규칙

- 항목 식별 키는 **카테고리 + 시술명**입니다. 같은 시술이 여러 카테고리에 노출되면 각각 따로 추적합니다.
- 비교 기준은 **할인가**이며, 정가는 참고용으로만 저장합니다. 가격은 원 단위 정수, VAT 별도입니다.
- 저장 필드: `category`, `name`, `list_price`, `sale_price`, `first_seen`, `last_seen`.
- 페이지에 같은 항목이 두 번씩 노출되어 `(카테고리, 시술명)` 기준으로 중복을 제거합니다.
- 첫 실행은 변동 요약 없이 기준 데이터만 저장합니다. `CHANGES.md`는 머리말만 있는 상태로 시작합니다.
- 변동이 없는 날은 `CHANGES.md`에 아무것도 추가하지 않습니다.
- 한 번에 신규·종료가 많이 감지되면(기본 10건 이상) `CHANGES.md`에서 하나의 묶음으로 요약하고,
  전체 목록은 접힌 영역(`<details>`)에 담습니다.
- 가격 이력은 날짜당 1개 스냅샷입니다. 하루 여러 번 수집해도 그날 행을 최신 값으로 교체하고,
  변동 요약도 직전 수집일 기준으로 다시 계산합니다.
- `updated_at`만 갱신되고 실제 가격 이력이 그대로인 실행은 커밋을 만들지 않습니다.

## GitHub에 올려 자동 실행하기

1. **공개 저장소**를 만들고 이 폴더를 push합니다.

   ```powershell
   git init
   git add .
   git commit -m "feat: 피부과 가격 추적기 초기 구현"
   git branch -M main
   git remote add origin https://github.com/내계정/저장소.git
   git push -u origin main
   ```

2. 저장소 **Settings → Actions → General → Workflow permissions**에서
   **Read and write permissions**를 선택합니다. (워크플로가 결과 파일을 커밋하려면 필요)

3. **Actions** 탭에서 `가격 추적` 워크플로를 열고 **Run workflow**로 한 번 수동 실행해 동작을 확인합니다.
   첫 실행은 기준 데이터만 저장합니다.

4. **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 `main` / `/(root)`로 설정합니다.
   잠시 뒤 `https://내계정.github.io/저장소/`에서 그래프가 열립니다.

5. `config.json`의 `repo_url`에 저장소 주소를 넣으면 그래프 페이지에서 변동 내역을 GitHub에서 바로 열 수 있습니다.

6. 4시간 간격으로 하루 6회 자동 실행됩니다(09:23 / 13:11 / 17:37 / 21:19 / 01:47 / 05:31 KST). `main`에 push할 때도 실행됩니다.
   Actions 탭에서 7일 연속 성공을 확인하세요. 수집 실패·구조 변경으로 실패한 날은 데이터가 그대로 남습니다.

> 비공개 저장소는 GitHub Pages 게시가 제한될 수 있어 공개 저장소를 전제로 합니다.
> 저장하는 가격은 병원 홈페이지에 이미 공개된 정보입니다.

## 수집 구조와 유지보수

파서는 2026-11-13 기준 실제 HTML 구조를 사용합니다.

| 데이터 | 선택자 |
| --- | --- |
| 가격 블록 | `.prd_list li.price_box` |
| 카테고리 | `p.prd_text` |
| 시술명 | `p.prd_info` |
| 정가 | `p.origin .num` |
| 할인가 | `p.discount .num` |

사이트 개편으로 선택자가 바뀌면 `tracker/scrape.py`의 상수만 고치면 됩니다.
추출 건수가 급감하면 Actions가 실패하므로, 사이트 구조 변경을 놓치지 않고 알 수 있습니다.
자동 접근이 차단되면 요청 헤더 보강이나 Playwright 전환을 검토하세요(현재는 `requests` + `BeautifulSoup`).

`robots.txt`는 확인 결과 메인 페이지(`/`) 접근을 허용합니다. 요청은 4시간 간격으로 하루 6회 보냅니다.
